# Generated-project acceptance

How we know a project generated by `scripts/create-project` works **on its own**: it lives
outside the blueprint, has its own git history and compose project, and uses only its own tools.
There are two kinds of evidence:
1. `scripts/validate-generated` runs every step of the brief on three representative projects.
2. A clean-room run: an agent with no knowledge of the blueprint builds a real feature in a fresh
   generated project, starting from its `AI_PROTOCOL.md`.

Machine: Apple M5 (10 cores, 16 GB), Docker in a colima VM (2 CPU / 4 GiB), macOS. Projects were
generated into a sibling directory outside the blueprint (`../uwsb-generated/<name>`). Each project's full JSON report is in its
`var/validation-report.json`.

What each step proves:

| `./dev check` | every canonical validation command: formatting, lint, audit, deny, secret scan, config check, Rust tests (including the authorization matrix and the 10 invariants), selected-module integration tests, TS bindings, frontend typecheck, lint, unit tests, build and bundle budget, Playwright E2E, deployment-tier verification, and the release image smoke (non-root, read-only, health checks, no public metrics) |
| `./dev up` + `./dev test --system` | frontend → API → PostgreSQL; login through the BFF (OIDC + PKCE, cookie session, CSRF); job → worker → outbound engine → provider; W3C trace context end to end; realtime SSE; audit; metrics; NATS and ClickHouse when selected |
| running server configuration | the server's startup `configuration` log line matches the selection (for example, Cedar is the active engine, not just compiled in) |
| module probes | a selected module's client library is in the server binary and its service runs; an unselected one is in neither, and its config is disabled |

## Limits of this evidence
- Identity used the in-repo mock OIDC provider. Live ZITADEL was verified in the blueprint
  (`frontend/tests/zitadel/`), not in generated projects; ZITADEL Cloud was not verified.
- One machine, one OS. CI on Linux has not run, because nothing has been pushed.
- Intermittent `sqlx::test` connect failures through the colima port forwarder were seen during
  validation; see `.ai/knowledge/KNOWN_ISSUES.md`.
