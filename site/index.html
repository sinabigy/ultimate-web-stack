Quickstart

The golden commands. Every one of them was run during release acceptance. Run the generator from the blueprint repository; the destination must be outside it. The app runs at http://localhost:5190 and the mock identity provider accepts any email.

# Create (from the blueprint repository; DEST must be outside it)
scripts/create-project ../my-product --name "My Product"                        # core profile, b2b auth
scripts/create-project ../my-saas --name "My SaaS" --profile performance --cedar   # + Redis cache, Cedar
scripts/create-project ../my-scale --name "My Scale" --profile distributed        # + NATS, ClickHouse

# Enter
cd ../my-product

# Validate the AI/project state
python3 tools/ai-check

# Run locally (http://localhost:5190, mock identity provider: any email)
./dev setup
./dev up

# Validate everything (lint, audit, tests, E2E, deployment tiers, release image)
./dev check

# Live proofs against the running stack
./dev test --system      # one journey through every component
./dev test --journey     # browser acceptance with screenshots
./dev test --drill       # failure drill (stops services briefly)

# Stop
./dev down

Prerequisites: Rust (pinned), Node ≥ 22, Docker (colima works: give it at least 6 GiB), Python 3.11+. A full ./dev check on a generated project took 6 min (core) to 22 min (distributed) in acceptance.

What we intentionally don't use

Negative results are listed on purpose: they are why some popular options are not in the default stack.

Rejected

  • Monoio / io_uring runtimeIdentical request handling in a Linux 6.8 container: io_uring was 0–24% slower than epoll, and slower than Tokio at every point. (ADR 0010)
  • An extra proxy hop by default (Pingora or nginx)Halves trivial-endpoint throughput on a shared host (143k → 66k req/s, +0.5 ms p50) and cuts DB-backed throughput 12–15% (nginx: 7–8%). (ADR 0009)
  • Redis session cacheThe gain is bounded at about ⅓ of DB round trips, at the cost of revocation latency or fail-open risk. Sessions stay in PostgreSQL and revocation stays immediate. (ADR 0004)
  • Fat LTO by default14% smaller than thin LTO for 38% more build time; no throughput gain. (ADR 0011)

No reliable win

  • PGO+7% plaintext, +9% json, +16% db, −3% cached: all within the baseline's 19% round-to-round spread. Adds a 241 s optimised build plus training.
  • mimalloc / jemallocInterleaved runs fall inside the baseline's own ±10% band. An earlier run that looked 26–36% slower was environmental drift.
  • Thread-per-core Tokio+3–7% on raw loops, but it would require non-Send executors across axum and sqlx.
  • Dragonfly instead of Redis54k vs 57k req/s at this scale (within noise). Kept as a tested adapter.

Architecture

Universal core

  • SolidJS + TypeScript + Vite, API types generated from Rust (ts-rs)
  • Rust, Tokio + axum, SQLx with compile-time checked SQL
  • PostgreSQL 18 as the single source of truth for sessions, jobs, events and audit
  • PostgreSQL job queue: SKIP LOCKED, leases, DLQ, idempotent enqueue
  • Realtime over SSE and WebSocket; outbound API engine with rate and concurrency controllers
  • W3C tracing end to end, Prometheus metrics on the internal ops port, JSON logs

Each optional module is a cargo feature plus configuration plus a compose profile, a CI service and a validation command. An unselected module is absent from all five, and the server's startup configuration log line proves what is active.

Security, with evidence

Each claim below is backed by a test or a live run. UI hiding is never counted as evidence.

BFF sessions over OIDC

The browser holds only an HttpOnly __Host- cookie. Tokens stay server-side, encrypted with AES-256-GCM. PKCE, nonce, state, CSRF tokens, MFA step-up. Nothing sensitive in localStorage.

RBAC or Cedar, default deny

Every org-scoped handler decides through the configured engine. Repositories accept only an OrgAccess proof, never an organization id from the client. System admin is a separate, MFA-gated trust level.

Tenant isolation: 404

A non-member gets 404, so existence is not revealed. Under load, the benchmark invariant saw 404 for every cross-tenant probe (10,429) and 401 for every missing credential (382,179 requests).

Append-only audit trail

Denied writes, escalation attempts and credential-scope denials are audited; the authorization matrix checks audit counts.

Authorization matrix, both engines

Runs over HTTP under RBAC and under Cedar: anonymous → 401; member → admin action 403; tenant A → tenant B 404; escalation 403; auditor 8 reads / 3 mutations → 200 / 403; a Cedar read policy enforced over HTTP (mutation-checked).

Browser acceptance

6/6 per role against the full stack, 27 screenshots. E2E: all 28 routes render, axe (WCAG 2.2 AA) in light and dark themes, no CSP violations, keyboard operability.

Failure drill: 14/14

  • PostgreSQL down: 503, and the session survives the outage
  • NATS or ClickHouse down: core works, readiness degraded, automatic recovery
  • Tampered session cookie: 401
  • Missing CSRF token: 403 csrf_failed

Live systemd test and release image smoke: pass / pass

  • systemd (Debian 12 container): start, check-config, migrations, non-root, worker, restart, graceful stop, crash restart
  • Release image (distroless): health, readiness, public surface, non-root, read-only, no baked secrets, restart, graceful shutdown
  • Public /metrics is an explicit 404; metrics live on the internal ops port

Found by tests, benchmarks, live runs and clean-room agents, then fixed with a regression test: rate limits keyed by IP instead of principal; public /metrics; an empty PATCH /orgs/{slug} that wrote without an authorization decision; a logout CSRF race; a worker crash-loop under systemd and Kubernetes; database outages answered 500 instead of 503.

Profiles

Choose infrastructure by the measured "when". Auth is a separate choice: basic, consumer, b2b (default) or enterprise, plus --cedar.

core default

PostgreSQL alone. Auth, dashboards, jobs, realtime, audit, in-process cache. For one host.

performance

+ Redis cache and shared rate limits. For several API instances; on one instance, in-process is 2.2× faster.

distributed

+ NATS/JetStream and ClickHouse. About 10× the PostgreSQL queue drain; about 24× faster cross-tenant aggregates.

full

+ Prometheus, Tempo, Loki, Alloy and Grafana dev stack, for observability development.

--with-gateway adds the Pingora edge workspace to any profile; --modules adds individual modules. Acceptance generated and validated three projects: minimal 22/22, SaaS 24/24, throughput 25/25 ./dev check.

What is not yet proven

Read this before you rely on the stack.

  • Kubernetes: static validation only. No live cluster was used.
  • ZITADEL Cloud and generic OIDC providers: configuration and discovery check only. Self-hosted ZITADEL was verified live in the blueprint, not in generated projects.
  • Benchmarks on CI: GitHub-hosted CI runs every functional, security and deployment check, but the benchmark numbers come from local runs on one machine.
  • TLS issuance: Caddy configuration validated, not exercised.
  • Single-machine benchmarks: every number comes from one Apple M5 host with services in a 2-CPU / 4 GiB VM. HTTP numbers are lower bounds and do not transfer to other hardware without re-measuring.
  • Still undecided: PGO, alternative allocators and thread-per-core Tokio need dedicated Linux hardware.
  • Not covered by the failure drill: network partitions between API instances, and disk-full on the database host.
  • Intermittent on the test host: sqlx::test connect failures through the colima port forwarder (pass on rerun), one historical E2E flake under full load, and one test that once exceeded its 20 s bound (not reproduced in 14 runs).
  • Delegated to the IdP: email delivery, password policy and MFA enrolment (simulated by the mock IdP in development).
  • Cosmetic: an empty "Job queues" chart card when no jobs are queued, and an empty organization switcher on not-found pages.
